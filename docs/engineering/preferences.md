# 개인 작업 선호

변경 빈도: 상대적으로 높음. 사용자가 표현한 선호를 짧게 유지한다.
이 파일은 프로젝트 아키텍처나 검증 기준을 재정의하지 않는다.

## 현재 확인된 선호

- 진행 상황과 결과는 한국어로 설명한다.
- 코드 품질 개선은 에이전트와 하네스의 리뷰·수정 루프로 진행한다.
- 다음 세션이 작업을 이어갈 수 있도록 작업 기억을 파일에 남긴다.
- 검증을 통과한 작업은 커밋·작업 브랜치 push·dev 대상 PR 생성까지 자동으로 마무리한다.
- PR 리뷰와 코멘트는 GitHub AI가 담당한다. 로컬 AI는 PR 코멘트를 게시하지 않는다.
- 최종 승인과 병합은 사람이 한다. test는 의미상 브랜치로만 둔다.
- 공통 원칙과 개인 성향을 서로 다른 Markdown 파일로 관리한다.

## 갱신 규칙

사용자가 새 선호를 명시하거나 기존 선호를 수정하면 이 파일을 갱신한다.
에이전트가 추측한 취향을 사실처럼 추가하지 않는다. 일회성 요청은
지속적인 선호로 일반화하지 않고 해당 작업 기록에 남긴다.
상충하거나 오래된 항목은 현재 선호로 교체하고 변경 이유를 작업 기록에 남긴다.
