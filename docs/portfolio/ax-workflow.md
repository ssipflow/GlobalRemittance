# AI를 활용한 개발과 통제

이 프로젝트의 AX 범위는 송금 서비스 개발의 작업 분해·구현·리뷰·검증·기억 복원을 AI 에이전트와 하네스로 운영한 것이다. 서비스 자체에 생성형 AI 기능을 넣은 것은 아니다. [대표 사례](case-studies.md)에서 절차가 실제 결함 발견과 설계 검증으로 이어진 과정을 볼 수 있다.

## 역할과 판단의 책임

| 역할 | 하는 일 | 경계 |
| --- | --- | --- |
| 사람 | 목표·요구사항·범위 결정, PR 최종 승인과 병합 | 최종 판단을 AI 통과 기록으로 대체하지 않음 |
| Coordinator | 작업 범위·완료 기준 등록, 위임, 결과 확인, 기억 갱신, 커밋·dev PR 생성 | 로컬 리뷰를 GitHub에 게시하거나 승인·병합하지 않음 |
| Implementer | 소유 파일 구현과 필요한 회귀 테스트 | 다른 작업자의 파일을 덮어쓰거나 커밋하지 않음 |
| Reviewer | 변경과 주변 코드의 결함·설계·회귀 위험 확인 | 읽기 전용, 내부 개선 결과 반환 |
| Verifier | 등록된 명령 실행과 실제 결과 보고 | 실패·미실행을 성공으로 처리하지 않음 |

사람의 기여로 기록된 것은 Goals Of Project 기반 전면 재구현 승인, 실행 범위를 dev PR까지로 제한한 결정, `own` 개선 진행 승인 등이다. 기술 선택은 코드·결정 문서와 작업 기록을 근거로 설명하며, 모든 구현 판단을 사람이 직접 했다고 주장하지 않는다. 예를 들어 소켓 타임아웃 도입은 [작업 기록](../harness/tasks/postgres-failure-modes.md)에 Coordinator 결정으로 남아 있다.

## 작업이 끝나는 조건

```mermaid
flowchart LR
    A[범위·검증 명령 등록] --> B[구현·기억 갱신]
    B --> C[독립 리뷰·검증]
    C -->|결함 또는 변경| B
    C -->|최신 snapshot 통과| E[로컬 커밋]
    E --> F[작업 브랜치 push·dev PR]
    F --> G[사람 승인·병합]
```

[`scripts/harness.py`](../../scripts/harness.py)는 HEAD·index·무시되지 않은 파일 내용과 모드를 snapshot으로 묶는다. 리뷰 이후 파일이 바뀌거나 검증 중 파일이 바뀌면 이전 근거로 `finish`할 수 없다. 작업 범위 밖 변경과 기존 staging을 거부하고, 작업 기억 갱신도 확인한다. 검증 명령이 성공해도 다른 snapshot이면 통과가 아니다.

범위를 늘릴 때는 `own --files ...`로 개별 파일을 등록한다. 추가 시각·파일은 로컬 상태에 남고 파일 내용이 바뀌면 재검토한다. `finish`는 로컬 커밋 단계이며, `publish`가 작업 브랜치를 push하고 dev PR을 확인해야 일반 작업이 완료된다. 커밋 후 수정은 기존 이력을 보존하는 후속 커밋으로 처리한다.

## 자동화가 증명하지 않는 것

`attest-review`는 Coordinator가 실제 독립 리뷰 결과를 확인해 기록하는 명령이다. 하네스가 리뷰어의 독립성이나 판단 품질을 인증하지는 않는다. 직접 Git 명령과 동시 파일 수정을 막는 보안 장치도 아니다. `own`은 이미 수정된 파일도 등록할 수 있어 기존 사용자 변경을 배제할 책임이 Coordinator에게 남는다.

state·작업 기록·결정 문서는 다음 세션의 출발점이고 실제 상태는 코드·Git·PR과 다시 대조한다. 전체 대화와 비밀 값은 기억에 넣지 않는다. 작업 기록은 과거 시점의 근거라 당시의 미검증 항목이 남을 수 있으며, 현재 검증 범위는 [검증 문서](validation.md)를 따른다.

시간 절감률·비용 대비 생산성·AI 없이 수행한 대조군은 측정하지 않았다. 효과는 생성 코드량 대신 재현된 결함, 수정 전후 검증, 오래된 snapshot의 커밋 거부 같은 확인 가능한 결과로 제시한다. 사용 절차는 [하네스 워크플로우](../harness/obsidian-workflow.md), 정책 원본은 [workflow](../../.codex/instructions/workflow.md)다.
