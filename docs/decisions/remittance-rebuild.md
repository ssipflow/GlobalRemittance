# 송금 서비스 전면 재구현

- 배경: 사용자가 기존 애플리케이션 전면 교체를 요청하고 Goals Of Project를 새 기준으로 지정.
- 선택: Java 17 호환, Spring Boot, H2를 유지하고 domain/application/adapter/bootstrap으로 새 구현.
- 도메인: 금액·수수료·환율·만료 규칙을 프레임워크와 분리한다.
- application: 저장소/시간/환율/암호화/토큰/트랜잭션 포트로 사용 사례를 조정한다.
- persistence: JPA 모델은 외부 어댑터에 둔다. 사용자의 DB 행 잠금으로 동일 사용자 접수를
  직렬화하고, 한도 조회와 견적 접수를 하나의 트랜잭션으로 처리한다.
- 한도: 견적에 고정한 순송금 USD 금액(USD 소수 2자리 HALF_UP)을 접수 일자에 합산한다.
  한도와 같은 금액은 허용하고 초과만 거부한다. 다른 사용자 거래는 독립적이다.
- 시간: 저장은 UTC Instant, 표시는 Asia/Seoul. 만료 순간(now >= expiry)은 거부한다.
- 금액: 이진 실수 대신 BigDecimal. 환율은 최대 소수 12자리, 금액은 Currency 규칙.
- 보안: BCrypt는 복호화할 수 없는 비밀번호 해시, ID 번호는 랜덤 nonce AES-GCM.
  토큰/AES 키는 환경변수, 테스트 값은 테스트 환경에 한정한다.
- 환율: 제공처 미지정이므로 구성값 어댑터를 사용한다. 실제 시세 제공 어댑터는 이후 교체 가능.
- 오류: 견적 만료의 원문 오타 QUOTE_EXPRIED를 계약으로 유지한다. 내부 원인과 민감정보는
  오류 본문에 공개하지 않는다.
- 대안/비용: 메모리 잠금은 다중 인스턴스에 한계가 있어 DB 잠금 선택. 정적 환율은
  재현성을 얻지만 최신 시장 시세를 제공하지 않는다. H2는 과제 환경이며 운영 검증을 대신하지 않는다.
- 범위: 기존 src 전체와 실행 README를 교체하고 Git 이력·하네스·개발 컨벤션을 보존한다.
  한글 주석은 불변식과 선택 이유를 설명한다. API를 기계적으로 번역하는 주석은 피한다.

## 반올림과 입력 경계

- 원화 입력은 최대 소수 12자리까지 받고 HALF_UP로 0자리로 정규화한 후 수수료 구간을 선택한다.
- ratedFee는 sourceAmount*feeRatio를 KRW 0자리 HALF_UP로 반올림하고 fixedFee를 더한다.
- 환율은 HALF_UP 12자리로 정규화하고 0 이하 또는 저장 범위 초과는 거부한다.
- DECIMAL(22,12)의 정수부는 10자리이므로 입력과 계산 결과의 저장 범위를 검사한다.
  과도한 지수 표현은 큰 자릿수 연산 전에 거부한다.
- 접수 오류 우선순위는 인증→소유권/존재→중복→만료→한도다.
- 이력은 접수시간 내림차순, 동일 시각은 ID 내림차순으로 고정한다.
