# 실제 환율 공급처를 연동하지 않는다

- 배경: 백로그에 "실제 환율 공급처 어댑터"가 남아 있었다. 환율 신선도 정책과 지연·장애를 주입하는 모의 공급처(`simulated`)는 이미 구현·검증했다.
- 결정(사용자, 2026-10-19): 적절한 외부 환율 API를 찾지 못해 이 항목을 백로그에서 삭제한다. 환율은 설정 환율(`configured`)과 모의 공급처로 유지한다.
- 근거: 공급처 없이도 정책(기준 시각 지연 초과 시 `RATE_STALE`, 조회 실패 시 `RATE_UNAVAILABLE`)과 오류 계약을 시연·검증할 수 있다. 연동 자체는 포트폴리오의 핵심 주장(정확성·동시성·멱등성)과 직접 관련이 작고, 선정 기준 없는 임의 공급처에 의존하면 재현성이 떨어진다.
- 남는 한계(그대로 유지): 실시간 시세 없음, 타임아웃·재시도·서킷 브레이커·다중 공급처 미구현, 환율 조회가 DB 트랜잭션 안에서 일어남, 견적에 환율 기준 시각 미저장([설계 문서](../application/design.md)에 기록됨).
- 재개 조건: 공급처를 정하면 새 작업으로 시작한다. 그때 조회 위치(트랜잭션 밖)와 견적의 기준 시각 저장(스키마 변경)을 함께 설계한다.
