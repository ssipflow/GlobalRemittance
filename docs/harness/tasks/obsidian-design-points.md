# obsidian-design-points

- 배경: 사용자가 "송금은 금융 도메인이라 데이터 정합성과 동시성에 민감한데 설계 포인트에 이 내용이 정리되지
  않았다"고 지적. 정합성·동시성 설명이 design.md의 여러 절에 흩어져 있었다.
- 절차 메모: 이전 task(obsidian-docs-rewrite)는 publish되어 reopen 불가(unpublished committed만 가능).
  같은 브랜치에서 새 task를 등록하고 publish가 기존 PR #13을 재사용하도록 했다.
- 변경 방침: design.md 맨 앞에 정합성 불변식 표(불변식·깨지는 상황·방어·검증 테스트), 동시성 경쟁
  시나리오(잠금 없음/있음 시퀀스), 읽기 일관성, 장애·재시도, 보증하지 않는 것을 둔다. 기존 세부 결정은 유지.
- 정직성: docs/decisions에 기록된 대안 비교는 '메모리 잠금 대신 DB 잠금' 하나뿐이다. 그 외 대안
  (낙관적 락, 직렬화 격리, DB 제약)은 과거 결정이 아니라 현재 분석으로 표기한다.
- 완료 기준: 모든 사실을 코드·테스트와 대조, 독립 리뷰, 하네스 검증, PR #13 갱신, 옵시디언 재동기화.

## 변경 요약
- design.md: 설계 우선순위 5개, 정합성 불변식 표(방어 수단·확인 테스트), check-then-act 경쟁을 잠금 없음/있음
  시퀀스로 설명, 다른 방식의 한계 분석(과거 결정 기록은 메모리 잠금→DB 잠금 하나뿐임을 명시), 읽기 일관성,
  장애와 재시도, 보증하지 않는 것(앱 수준 불변식·단일 DB 잠금·격리 수준 미지정·H2 2스레드 테스트).
  기존 세부 결정(금액·견적·DB 집계·keyset·시간·인증·테스트)은 하위 절로 유지.
- overview/architecture: 주요 설계로 안내하는 문장만 보강.
- 내부 리뷰 반영: 재작성 중 빠졌던 두 사실(같은 사용자 접수의 직렬화 처리량 대가, 견적별 USD 2자리
  반올림 값의 합산)을 복원했다. 롤백 검증 행은 '간접 확인'으로 표기, 중복된 멱등성 참조 줄 삭제.
