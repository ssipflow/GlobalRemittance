# Codex 하네스 초기 구성

## 목적과 변경

포트폴리오 개선을 작업 단위의 구현 → 독립 리뷰 → 검증 → 수정 → 기억 → 커밋으로 실행한다.
메인 Coordinator와 프로젝트 에이전트 implementer/reviewer/verifier를 구성했다.
모델은 부모 설정을 상속하며 동시 자식은 3개로 제한한다.

AGENTS.md는 시작 시 기억 복원과 역할별 위임을 요청한다. SessionStart는 복원 안내,
PostToolUse는 변경 snapshot 알림, Stop은 등록된 작업만 최대 3회 계속하도록 한다.
Python 표준 라이브러리 하네스는 작업 소유권, 최신 리뷰/검증, 기억 갱신을 확인한 뒤
명시적 파일 목록을 로컬 커밋한다. 루프 상태와 실행 로그는 .harness에만 저장한다.

## 검증 근거

- `python3 -m unittest discover -s scripts/tests -v`: 12개 통과.
- `git diff --check`: 통과.
- 독립 reviewer 재검토: 블로킹 결함 없음.
- 독립 verifier: 테스트 12개, diff 검사, 설정 TOML 4개와 훅 JSON 파싱 통과.
- 회귀 검증: 정상 커밋, 삭제 파일, 기존 사용자 변경 거부, 범위 밖 변경 거부,
  오래된 검토/검증 거부, 검증 실패/파일 변경, Stop 상한, 중단 후 승인 무효화,
  커밋 전/후 Git 훅 변경 탐지, timeout 자식 프로세스 종료.
- 실제 Codex 세션에서 훅을 신뢰한 후 lifecycle 이벤트가 실행되는 통합 검증은 아직 하지 않음.
- 애플리케이션 테스트는 실행하지 않음. 테스트 DB/외부 API 격리가 먼저 필요함.

## 다음 행동

새 Codex 세션에서 프로젝트와 `/hooks`의 훅을 신뢰한다.
깨끗한 작업 트리에서 테스트 환경 격리 작업을 등록하고 개선 루프를 실행한다.
초기 설정은 하네스를 만드는 작업이므로 begin 게이트 도입 전의 변경이다.
독립 리뷰와 검증을 거쳐 Coordinator가 명시적 파일만 최초 커밋한다.
커밋 식별자는 이 파일의 Git 이력으로 확인한다.
